# Contributing

Thank you for helping with AedwenOS. Issues and pull requests are welcome.
Useful contributions at this stage include test reports from real hardware and
virtual machines, fixes to the Calamares configuration, shell and theme work,
and branding assets.

By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
Report security problems privately, as described in [SECURITY.md](SECURITY.md),
not in a public issue.

## Reporting bugs

Use the **Bug report** issue form. Please include the ISO version (its file
name), whether you booted it in a VM or on real hardware, and describe the host
system. AedwenOS is UEFI-only for now; in VirtualBox, enable Settings → System →
Enable EFI, and keep Secure Boot off.

## Getting set up

You need an x86-64 Arch-based host. The [README](README.md#building-the-iso)
has the full build and test instructions; in short:

```sh
scripts/build-localrepo.sh      # once: builds calamares, the Aedwen packages and the UI font
./build.sh                      # builds the ISO into out/ (asks for sudo itself)
./test-vm.sh                    # boots the newest ISO in QEMU
```

Run `scripts/check-shell.sh` after changing a shell widget or after a Plasma
update.

## Making a change

1. Fork the repository and branch from `master` (for example `feat/short-name`
   or `fix/short-name`).
2. Keep a pull request to one change, and say how you tested it. A change that
   you could not boot-test should say so.
3. Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):
   `feat(ui): add welcome app`, `fix(ci): support optional v-prefix`. The scope is
   optional.
4. Open the pull request; the template lists what to check.

Package changes go in `iso/packages.x86_64` only: Calamares and
`aedwen-install` both read it. Put every comment on its own line (the file
explains why).

## Theme and shell changes

Much of the theme is generated by scripts (colours from `scripts/palette_lib.py`):
the KDE colour schemes and `kdeglobals`, GTK CSS, cursors, sounds, Plymouth
frames, the Limine wallpaper, the Calamares `Theme.qml`/stylesheet, the Plasma
theme (`desktoptheme/aedwen`) and the shell's icon font and eagle. Change the
matching `scripts/generate-*.py` and re-run it rather than editing its output,
or the next run will overwrite your edit.

AedwenOS has two design variants: Material 3 Expressive (what ships) and stock
Material 3 ("baseline"). Shape values (corner radii, the hover shape of round
controls, motion) live in `SHAPES` in `scripts/palette_lib.py`. A generator
that draws shapes should take the variant and read them from there, not
hard-code radii; `generate-aurorae-theme.py` and `generate-gtk-theme.py
--variant` already do.

Other generators: `generate-icons.py` writes the app, folder, drive and
symbolic icon theme (`Aedwen-Icons`); `generate-app-themes.py` the Konsole
colour scheme and the Kate editor themes; `generate-desktop-wallpaper.py` the
wallpaper. The accent-following ones are re-run on the user's machine by
`aedwen-icons` and `aedwen-apps` (and `aedwen-cursors`), which `build.sh` copies
into the image together with their generator, so those scripts must stay
runnable from `/usr/lib/aedwen` with only what `build.sh` installs there.

A few of those have more than one output:

- `generate-aurorae-theme.py` writes the window title bars,
  `aurorae/themes/AedwenOS-{Dark,Light}` and `AedwenOS-Baseline-{Dark,Light}`.
  Their fills follow the colour scheme; only the title text colour is fixed,
  which is why there's a dark and a light copy. `etc/xdg/kwinrc` and the
  global themes select them.

- `generate-cursors.py --all-static` writes every shape family in the dark
  and light styles (`icons/Aedwen-<Family>-<Style>`) plus the default
  `Aedwen`. The accent and tonal styles follow the user's accent colour, so
  they're built on the user's machine by `aedwen-cursors` (with this same
  script, which `build.sh` copies into the image) and rebuilt by the
  `aedwen-cursor-accent` user unit when the accent changes.
- `generate-sounds.py` writes the design's tones plus symlinks for the other
  sound names KDE's notifications ask for (`ALIASES`).
- `generate-limine-wallpaper.py` also writes `usr/share/limine/aedwen-limine.conf`,
  the boot menu's look. Both the installed system's `limine.conf` and the live
  ISO's start from it. The ISO is built with systemd-boot (archiso has no Limine
  mode) and `build.sh` then swaps Limine into its EFI partition with
  `scripts/limine-live-esp.sh`.

The lock screen (`look-and-feel/org.kde.aedwen.desktop/contents/lockscreen`),
the logout screen (`.../contents/logout`) and the login screen
(`usr/share/sddm/themes/aedwen`) are Plasma 6.7's own QML, restyled. They
keep Plasma's logic and interface, so after a Plasma update that changes
those files in plasma-workspace / plasma-desktop, re-copy the upstream
versions and re-apply the AedwenOS styling (each file's header lists what
differs). The lock screen falls back to KDE's if it gets out of date. The
login splash (`.../contents/splash`) is our own and matches the Plymouth
boot splash.

The top bar and dock widgets (`iso/airootfs/usr/share/plasma/plasmoids/org.aedwen.*`)
and their QML modules (`iso/airootfs/usr/lib/qt6/qml/org/aedwen/`) are plain
QML. Before sending a change to them, run `scripts/check-shell.sh`, which loads
each widget against your installed Plasma and fails on QML errors.

## Installer and packages

The Calamares configuration is `iso/airootfs/etc/calamares/`; its pages are QML in
`branding/aedwenos/` (the "Extras" step is `notesqml.qml`, with the packs listed in
`etc/calamares/packs`). Changes to the Aedwen packages under `packages/`
(`aedwen-tools`, `aedwen-qstyle`, `aedwen-decoration`, `ttf-roboto-flex`,
`calamares`) are built by `scripts/build-localrepo.sh`; bump `pkgrel` when a
rebuild must be picked up.
